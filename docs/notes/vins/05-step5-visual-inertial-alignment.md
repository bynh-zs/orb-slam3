# STEP5 · 视觉惯性对齐（单目的尺度治愈）

## 这一步解决什么问题

STEP4 交出来的位姿形状对、长度错。STEP5 的任务是把「形状对」变成「米制对」，同时顺手解出重力和陀螺零偏。

一句话概括：**用 IMU 的加速度测量，把单目丢掉的尺度补回来**。

## 真实 VINS 做了什么

对应 `initial/initial_alignment.cpp`，官方在这一个文件里做了三件事，顺序不能反：

### 5.1 先解陀螺零偏 `solveGyroscopeBias()`

视觉给了相邻帧的相对旋转 `R_ck_ck+1`，IMU 预积分也给了相对旋转 `ΔR_imu`。两者在理想情况下应该一致，差异只可能来自陀螺零偏 bg：

```
残差 ≈ [ (R_icᵀ · ΔR_imu(bg) · R_ic) · R_ck_ck+1ᵀ ] 的旋转向量部分
对 bg 求最小二乘，每个帧对一项，迭代 1~2 轮
```

为什么要先解 bg：如果 bg 不准，后面线性对齐里的重力方向会被 bg 的误差带着歪。这是「先校陀螺，再校重力」的因果，不是任意排序。

`R_ic` 是相机到 IMU 的外参旋转。本仓库直接从 `mav0/cam0/sensor.yaml` 读，不做在线标定（在线标定是 `initial_ex_rotation.cpp` 的 `CalibrationExRotation`，属于另一条路径）。

### 5.2 线性对齐 `LinearAlignment()`

把三件事塞进一个线性方程组：

```
未知量 x = [ v_0, v_1, ..., v_n,  g,  s ]
规模    = 3(n+1) + 3 + 1
```

每个相邻帧对贡献一组残差，形如：

```
视觉平移 (p_i → p_j) 与 IMU 预积分 Δp 的差
+ 重力在这段时间里的二次项 0.5 · g · t²
+ 速度项 v_i · t
```

写成 `A x = b` 后一次解出来。注意这里的 `A` 是稀疏的，`g` 和 `s` 是全局共享未知量，所以每个帧对都和 g、s 耦合 —— 这正是「用重力定尺度」的数学形态。

### 5.3 重力细化 `RefineGravity()`

线性对齐解出的 g 只是近似。真做法是把它约束在模长为 9.8（本数据实测 9.633）的球面上，用切平面两参数扰动迭代：

```
g = |g| · ( b + w₁·b₁ + w₂·b₂ )
其中 b 是当前重力方向单位向量，b₁、b₂ 是球面切平面的正交基
迭代 2 次，每次重解
```

球形参数化的意义：避免「g 长度乱飘」。如果放开 3 个分量随便解，尺度 s 会和 |g| 的长度耦合，解出 (s=2, |g|=4.9) 这种整体缩放解，物理上等价但没法用。

## 本步的验收标准

| 指标 | 预期 | 依据 |
|---|---|---|
| 尺度 s | 量级合理（0.1~10 之间，非 1e-6 或 1e6） | 无尺度解 × s 应接近米制 |
| 重力方向 | 与 STEP1 实测 (8.47,-0.22,-4.58) 方向同族 | IMU 横装，重力不在 z 轴 |
| 陀螺零偏 | 与静止段均值 (-0.007,-0.017,0.080) 同量级 | STEP1 已给出先验 |
| 对齐后 Δp 残差 | 明显小于对齐前 | 线性对齐是否真的起作用 |

可视化：重力方向在单位球上的迭代轨迹（起点 → 收敛点）、尺度 s 随迭代的收敛曲线。

## 为什么这一步不能跳过

有人会想：单目没尺度，那我把轨迹整体归一化一下不就行了？不行 —— 因为尺度不是常数。滑窗内每一段的尺度必须一致才能拼成连续轨迹；而 s 是一个**全局量**，只能通过 IMU 的加速度观测一次性解出。少了解 s 这一步，STEP6 的紧耦合优化里视觉残差和 IMU 残差就没法放在同一个量纲上比较。

## 常见错误

- 先解重力再解零偏：bg 的误差会污染 g 的估计。
- 重力用 3 个自由分量解，得到与尺度耦合的退化解。
- `R_ic` 用单位阵凑。IMU 横装时 R_ic 偏离单位阵很远，用单位阵会导致对齐残差整体偏大而误判「数据有问题」。
- 把 |g| 写死 9.8，而实测是 9.633 —— 差 1.7%，会在轨迹末端累积成米级偏移。
