# STEP1 · 读 IMU，摸清传感器脾性

## 这一步解决什么问题

在算任何几何之前，先确认 IMU 数据本身是能用的。要回答四个问题：

1. 时间戳是否单调、间隔是否恒定？——决定后面能不能用固定 dt 做积分。
2. 采了多少个点、频率多少？——决定每两个图像帧之间能塞进多少个 IMU 采样（EuRoC 是 200Hz 对 20Hz，10 个）。
3. 静止段的陀螺读数是多少？——这个残留值就是陀螺零偏 bg，STEP5 要把它解出来减掉。
4. 加速度的模长和方向是什么？——模长应该贴着 9.8；方向告诉你 IMU 是怎么装在机身上的。

第 4 条是 VINS 特有的、单目 SLAM 里完全不存在的一件事：单目只需要图像，VINS 必须知道重力在哪。

## 怎么做的

读 `mav0/imu0/data.csv`。格式是逗号分隔，第一行是注释表头：

```
#timestamp [ns],w_RS_S_x [rad s^-1],w_RS_S_y,w_RS_S_z,a_RS_S_x [m s^-2],a_RS_S_y,a_RS_S_z
```

两个细节容易踩：

- 时间戳单位是**纳秒**，用 `int64_t` 存。用 double 存 1.4e18 级别的整数会丢精度，相邻差值算出来是错的。
- 以 `#` 开头的行要跳过，不能当数据解析。

读进来后统计：总采样数、时间戳差分（min/max/mean）、三轴陀螺均值与方差、三轴加速度均值与模长。

## 图怎么读

两张三轴曲线：

- **陀螺图**：三条线基本贴在 0 上，说明整段数据里角速度很小（飞行器悬停/缓慢起飞）。线上那点非零残留不是噪声，是零偏，`z` 轴约 0.080 rad/s 是三个分量里最大的。
- **加速度图**：模长恒定在 9.633，接近 9.8 但不等 —— 差的这 0.17 一部分来自传感器标定，一部分来自这段数据本身有小幅运动。

关键读数是三条线的**相对高低**：`ax ≈ 8.5` 明显最高，`az ≈ -4.6` 明显偏低。这说明重力几乎全压在 x 轴上、z 轴只分到一半。换成人话：**IMU 是横着装的，重力不在 IMU 的 z 轴方向**。

这正是 VINS 初始化的第一个坑：任何「假设重力沿 -z」的代码在这里都会直接错。重力方向必须从数据里估出来，不能写死。

## 验收标准与实测值

| 指标 | 要求 | 实测 |
|---|---|---|
| 采样总数 | — | 36820 |
| 相邻间隔 | 恒 5.000 ms | 5.000 ms |
| 等效频率 | 200.0 Hz | 200.0 Hz |
| 静止段陀螺 | 接近 0 | (-0.007, -0.017, 0.080) |
| 加速度模长 | ≈ 9.8 | 9.633 |
| 重力方向（归一化前） | 不在 z 轴 | (8.47, -0.22, -4.58) |

间隔恒为 5.000ms 是这一步最有价值的结论：后面 STEP3 可以直接用固定 dt 积分，不必逐点查表。

## 本步产出的两个结论，后面要用

1. `bg` 的初值 ≈ 静止段均值 (-0.007, -0.017, 0.080)（按「测量 = 真值 + 零偏」的约定，静止时真值为 0，均值即零偏）。STEP5 会用它做线性对齐。
2. 重力方向不在机体系 z 轴。STEP5 的重力细化必须在球面上做两参数扰动，不能用「g = (0,0,-9.8) 加一个修正量」这种线性化方式开局。

## 常见错误

- 时间戳当秒用，`dt` 直接错 9 个数量级。
- 用 float/double 存纳秒，相邻时间戳相减得到 0。
- 把加速度模长当常量 9.8 写死进后续积分，误差从 0.17 m/s² 开始累积。
