# STEP6 · 滑窗紧耦合优化与边缘化

## 这一步解决什么问题

STEP4 的 BA 只优化「位姿 + 3D 点」，用的是纯视觉的重投影残差。STEP5 给了尺度、重力、速度、零偏。到了 STEP6，才第一次把**视觉残差和 IMU 残差放进同一个优化问题**里，联合求解。

这就是「紧耦合」三个字的实际含义：不是先算视觉位姿、再拿 IMU 去融合（那是松耦合），而是在一个代价函数里同时最小化两类残差。

## 滑窗与状态量

滑窗取 10 帧（官方默认 `WINDOW_SIZE = 10`）。每帧的状态量：

```
[p, q, v, ba, bg]   位置、姿态、速度、加速度零偏、陀螺零偏
```

每个被跟踪的特征点用**逆深度 λ** 参数化（而不是直接存 XYZ），挂在它第一次被观测到的那个帧上。这样参数维度更低，且天然限制了「深度跑到无穷」。

总参数维度约：10 × 15 + 特征数 × 1。

## 三类残差

| 残差 | 来源 | 约束什么 |
|---|---|---|
| IMU 预积分残差 | 相邻帧之间的 ΔR、Δv、Δp 与状态推算值之差 | 帧间运动学一致性 |
| 视觉重投影残差 | 3D 点投影回图像与观测值之差 | 结构与位姿一致性 |
| 边缘化先验 | 被移出滑窗的老帧留下的信息 | 不让滑窗「忘记」历史 |

IMU 残差带零偏雅可比：`ΔR(bg)`、`Δv(bg,ba)`、`Δp(bg,ba)` 都要对 bg、ba 做一阶展开。这就是 STEP3 里说的「零偏修正项」在这里才真正用上。

## 边缘化怎么工作

滑窗满了要踢掉最老一帧。不能简单丢掉 —— 丢掉的观测信息再也回不来，会表现为「轨迹在滑窗边界处突然跳一下」。

标准做法是 **Schur 补**：

```
把 H Δx = b 按「保留的状态」和「要丢的状态」分块：
[ H_mm  H_mr ] [Δx_m]   [ b_m ]
[ H_rm  H_rr ] [Δx_r] = [ b_r ]

消掉 Δx_r： (H_mm − H_mr H_rr⁻¹ H_rm) Δx_m = b_m − H_mr H_rr⁻¹ b_r
```

得到的 `H_mm − H_mr H_rr⁻¹ H_rm` 就是「先验因子」，它把老帧的信息压缩成一个约束加回优化。`H_rr` 求逆用特征值分解（`SelfAdjointEigenSolver`），因为要丢的状态块本身可能是奇异的。

先验因子的实现是最容易出错的地方：要保留它的切空间（`sqrt_info` 的 Cholesky 因子）和线性化点，每次优化时都在那个点附近做一阶展开。

## 验收标准

| 指标 | 预期 |
|---|---|
| 优化后平均重投影残差 | 比 STEP4 的纯视觉 BA 更低或相当 |
| IMU 残差 | 不出现 10⁴ 量级（出现说明量纲或时间对不上） |
| 滑窗边界处轨迹 | 无跳变 |
| 边缘化前后 | 同一帧的位姿变化 < 厘米级 |

可视化：每次优化迭代的残差下降曲线、滑窗内各帧的协方差椭圆、被边缘化的帧在轨迹上的标记。

## 常见错误

- 视觉残差用像素坐标、IMU 残差用米制，两个量纲直接相加 —— 必须各自乘信息矩阵（协方差的逆）。
- 边缘化时把「保留状态」和「丢弃状态」搞反，先验因子会变成负信息矩阵，优化直接跑飞。
- 先验因子的线性化点没有固定，每次迭代跟着状态走，等于把先验变成了软约束，滑窗会慢慢飘。
- 特征点用绝对 XYZ 而不是逆深度，深度初值给得离谱时优化不收敛。
