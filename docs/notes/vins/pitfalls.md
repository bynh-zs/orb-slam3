# 踩坑记录

这份文档记录的不是「教科书上应该注意什么」，而是**实际调试过程中真的撞到的墙**，每条尽量给出当时的输出，方便对照。

---

## 1 · `undistortPoints` 必须传点集，不能传单点

第一次编译就在这挂了：

```
error: no matching function for call to 'undistortPoints(cv::Mat&, cv::Mat&, cv::Mat&, cv::Mat&, ...)'
```

`undistortPoints` 有两种重载，输入分别是 `InputArray` 点集和单点。传 `Mat(2,1)` 的单点时编译器选了不匹配的那个，且后续 `n1[0]` 的下标也越界。

**做法**：统一用 `std::vector<cv::Point2f>`，一次算一批：

```cpp
std::vector<cv::Point2f> src, dst;
src.push_back(px);
cv::undistortPoints(src, dst, K, D);   // dst[0] 就是归一化坐标
```

## 2 · 强畸变相机：重投影残差不能在像素空间比

这是本次最贵的一个坑，症状是「重投影检查把几乎所有点都判成坏的」。

v2 版本在像素空间做检查：把 3D 点用针孔模型投回图像得到 `u,v`，与观测到的像素比，阈值 2px。结果：

```
初始三角化只剩 1 个点
BA 123px → 60px，12 次迭代不收敛
```

根因：EuRoC cam0 的 `k1 = -0.28340811` 是强畸变。用**无畸变针孔模型**投出来的点和**带畸变**的原始像素，在图像边缘能差 10~20px。这不是点错了，是模型不一致 —— 边缘的正确点被系统性当成外点删掉，剩下的全是图像中心的点，几何退化。

**做法**：所有几何计算（三角化、重投影检查、BA 残差）统一在**去畸变归一化坐标**空间做。每个观测存两份：

```cpp
struct Obs {
    cv::Point2f px;   // 原始像素：只用于可视化、把误差换算成 px 给人看
    cv::Point2f nv;   // undistortPoints 结果：所有几何计算用它
};
```

归一化空间的阈值 `NORM_THR = 0.01`，约等于 4.6px（因为 `fx ≈ 458`，`0.01 × 458 ≈ 4.6`）。

**教训**：当「误差」和「观测」来自不同投影模型时，误差不是误差，是模型差。

## 3 · `triangulatePoints` 的齐次符号是随机的

同一条代码路径，只把输入从 `Mat(2,1)` 换成 `vector<Point2f>`，输出完全反转：

| 输入格式 | 过深度检查 | 过重投影检查 | BA 前误差 |
|---|---|---|---|
| `Mat(2,1)` | 416 / 419 | 10 | 0.48 |
| `vector<Point2f>` | 0 / 419 | 0 | nan |

原因是 `triangulatePoints` 内部对 4×N 齐次结果做 SVD，最小奇异值对应的特征向量符号是任意的 —— `X` 和 `-X` 是同一个数学解，但 `w` 的符号一变，归一化后的 `X.z` 就整体反号，全部点「跑到相机后方」。

**做法**：不要信任返回的符号，必须显式处理：

```cpp
cv::Mat X4;                        // 4×1 齐次
cv::triangulatePoints(P0, P1, a, b, X4);
if (std::abs(X4.at<double>(3)) < 1e-12) continue;   // 无穷远点，丢
if (X4.at<double>(3) < 0) X4 = -X4;                 // 统一成 w>0
cv::Point3d X(X4.at<double>(0)/X4.at<double>(3),
              X4.at<double>(1)/X4.at<double>(3),
              X4.at<double>(2)/X4.at<double>(3));
if (!(X.z > 0) || !std::isfinite(X.z)) continue;    // 深度检查放在这里
```

**边界情况**：`X4 = -X4` 本身不改变 `X = X4/w`（分子分母同时反号），所以它能修正「`w` 为负」这种情况，**不能**修正「点真的在相机后方」这种情况。两者现象一样、原因不同，必须靠 `X.z` 的符号判断，不能靠 `w`。

**教训**：几何库返回的符号不保证，凡是「方向」类结果都要自己归一化一次。

## 4 · make 失败后，旧二进制还在，输出会被误当验收

出现过好几次：`make` 报错（编译失败），但 `build/step4_sfm` 里躺着上一次成功的二进制。接着跑 `./build/step4_sfm`，输出了一堆数字和图，看起来「跑通了」，实际是**旧代码的结果**。

识别方法：

- `make` 的输出里必须看到 `[100%] Built target step4_sfm`。没有这一行就说明链接没完成。
- 编译报错时终端会出现 `make: *** [Makefile:xx] 错误`，此时后续任何运行结果都无效。
- 时间戳核对：`ls -l build/step4_sfm` 的修改时间必须晚于 `step4_sfm.cpp`。

**做法**：把「编译成功」和「运行」分成两次独立操作，中间看一眼有没有 `Built target`。不要在一条命令里 `make && ./run` 然后只看最后几行。

## 5 · `recoverPose` 的 t 符号不能用物理直觉判断

看到 `t = (-0.747, 0.433, -0.504)` 时，第一反应是「t.z < 0 说明相机在后退，EuRoC 是往前飞的，符号反了」。于是翻转 t：

```
过深度检查 = 0，过重投影 = 0，点云几乎为空
```

翻转后全部点落到相机后方 —— 说明**原来那个 t 的方向才是对的**。相机坐标系的 z 轴朝前，但 `recoverPose` 的 t 是「从相机1指向相机2」的平移方向在不同坐标系约定下的表达，`t.z < 0` 在 MH_01 起飞段完全可能是正确解。

**做法**：不靠直觉，靠数据。翻转前后各跑一次深度检查：哪个解让更多点落在两相机前方，就用哪个。这也是为什么深度检查必须放在三角化之后 —— 它是唯一可靠的符号判据。

## 6 · 归一化坐标上直接求本质矩阵，不如「像素空间求 F 再转换」

试过在归一化坐标上直接 `findEssentialMat`（跳过 K 的参与）：

```
F 内点 251 / 526
过重投影保留 11
PnP 内点 6 / 0 / 0 / 8
BA 前误差 4.37（≈2003 px）
```

换回「像素坐标求 F、再 `E = Kᵀ F K`」：

```
F 内点 419 / 526
过重投影保留 10
BA 前误差 0.48（≈221 px）
```

虽然两条路都没跑通，但内点数 419 vs 251 说明像素空间的 RANSAC 更稳。可能原因：`findEssentialMat` 内部对归一化坐标的数值尺度敏感（归一化坐标数量级在 1 附近，而 5 点法的采样要求亚像素级的阈值判定），像素坐标（几百的量级）反而数值条件更好。

**结论**：涉及 RANSAC 的鲁棒估计，优先在原始像素坐标做；拿到结果再转到归一化空间做精算。

## 7 · 视差选帧对了，但 PnP 帧选得太近

选帧逻辑遍历所有帧对、取平均视差最大者，命中 `(0,5)` 即帧 200 ↔ 帧 210，平均视差 244.9px —— 这个选择是对的。

但 4 个 PnP 帧是 202/204/206/208，帧 202 距参考帧 200 只有 0.1s，视差极小。结果：

```
PnP 帧202 内点 7
PnP 帧204 内点 0
PnP 帧206 内点 0
PnP 帧208 内点 8
```

帧204/206 内点为 0 尤其说明问题：它们夹在两个「有内点」的帧之间，逻辑上不该是 0。这提示 3D 点集合与这些帧的观测没有对上（可能是三角化后的点 ID 与观测 ID 映射错位），而不是单纯的视差问题。

**结论**：PnP 的输入点集必须和三角化输出的 ID 严格对应；视差太小的帧（间隔 0.1s）不适合单独做 PnP，官方也是在滑窗内挑间隔更大的组合。

## 8 · 多轮 sed 修改导致代码状态漂移

这是本次调试效率最低的地方。十几轮 `sed -i` 改同一个文件后，出现：

- 变量定义被删但引用还在（`'a' was not declared`）
- 同一行被插入两次
- 修改点落在错误的行号（文件行数已经变了）

到最后已经不确定「现在文件里到底是什么」。

**做法（按优先级）**：

1. 改动前 `cp step4_sfm.cpp step4_sfm.cpp.bak`。
2. 每次只改一处，改完 `grep -n` 确认落点，再编译。
3. 超过 3 处改动，直接**整篇重写文件**。重写比追踪 sed 的累积副作用便宜得多。
4. 出现「结果和预期不符但代码看起来对」时，第一件事是 `cat` 当前文件核对，不要基于记忆继续改。

## 附：一句话总结这八个坑

| 坑 | 一句话 |
|---|---|
| 1 | OpenCV 的点集接口不要喂单点 |
| 2 | 误差和观测必须来自同一个投影模型 |
| 3 | 齐次坐标的符号要自己归一化 |
| 4 | 编译没看到 Built target，运行结果一律作废 |
| 5 | t 的符号让数据说话，不让直觉说话 |
| 6 | RANSAC 优先在像素坐标做 |
| 7 | PnP 的点 ID 必须和三角化严格对应 |
| 8 | 改动超过三处就重写，别追 sed |
